# 온라인 계정 연결

이 프로젝트는 Firebase Authentication(이메일/비밀번호)과 Realtime Database를 사용한다. 게임 웹은 기존 GitHub Pages의 `/Wax-Ball/arena/`에서 제공한다. 무료 Spark 플랜으로 구성하며 Cloud Functions, 결제 연결, 유료 플랜은 요구하지 않는다.

## 서비스 설정

1. Firebase 프로젝트를 만들고 웹 앱을 등록한다.
2. Authentication에서 이메일/비밀번호 로그인을 활성화한다. 이메일 인증이 끝나야 게임 계정 데이터에 접근할 수 있다.
3. Realtime Database를 생성한다. 테스트 모드로 공개하지 않는다.
4. `database.rules.json`을 배포한다. 인증되지 않은 요청, 다른 계정의 데이터 접근, 기존 대전 수정·삭제, 잘못된 결과·난이도·필드·시간은 거부한다.
5. `js/account-config.js`에 웹 앱의 공개 `apiKey`, `projectId`, Realtime Database의 `databaseURL`을 입력한다. URL 끝의 `/`는 제거한다. 관리자 키와 서비스 계정 파일은 코드나 Git에 넣지 않는다.
6. Authentication의 승인된 도메인과 API 키 HTTP 리퍼러 제한에 `gamjadough.github.io`를 추가한다. 개발 검증을 위해 필요하면 `localhost`와 `127.0.0.1`도 승인한다. 제한 대상 API에는 Identity Toolkit, Secure Token이 필요하다.

Firebase 기본 이메일 작업 화면에서 인증 및 비밀번호 재설정을 완료한다. 인증 후 게임으로 돌아와 로그인한다. 미인증 계정은 로그인 탭에서 이메일·비밀번호를 입력하고 인증 메일을 다시 요청할 수 있다.

## 저장 동작

- 게스트 기록은 기존 브라우저 저장 키에 유지하며 계정 기록과 자동 합치지 않는다.
- 로그인 토큰은 탭의 `sessionStorage`에 저장한다. 비밀번호는 저장하지 않는다. 새 탭·다른 기기에서는 다시 로그인한다.
- 온라인 기록은 UID별 경로의 변경 불가능한 대전 결과다. 서버 저장 시각을 사용하며 같은 대전 ID는 한 번만 생성할 수 있다.
- 골드는 저장된 승리 수 × 50이다. 클라이언트가 별도의 골드 금액을 저장하거나 기존 기록을 변경할 수 없다. 승리 확인은 현재 로컬 AI 게임 결과를 사용하므로 경쟁 게임 수준의 부정 플레이 방지는 서버 전투 검증이 추가로 필요하다.
- 접속 오류 시 계정별 브라우저 대기열에 결과를 보관한다. 자동 재접속 또는 계정 창의 동기화로 다시 저장한다. 서버 응답 전에는 지급 완료로 표시하지 않는다.
- 브라우저 저장까지 실패하면 창을 유지하도록 안내하고, 미저장 상태의 로그아웃을 막는다. 브라우저 데이터를 삭제하면 아직 서버로 전송하지 못한 결과는 사라질 수 있다.
- 전투 중에는 계정 변경을 막는다. 초기 로그인 복원이 끝날 때까지 대전 시작을 잠시 비활성화한다.
- 계정별 모든 대전 결과로 합계를 계산하고 최근 100개를 화면 상태에 유지한다. 기록이 많이 쌓이면 조회 데이터가 늘어나므로 운영 규모가 커질 때 서버 집계를 도입한다.

## 검증

`npm run test:accounts`는 인증·세션 갱신·대기열 실패 복구를 가상 서버로 검사한다. `tests/accounts_browser.py`는 Playwright Python으로 실행하는 브라우저 연동 검사다. 실행 시 개발 서버 주소를 `TEST_URL`로 지정할 수 있다. 이 검사는 가상 Firebase 응답을 사용하므로 실제 이메일 발송, 데이터베이스 규칙, 기기 간 연동이 검증된 것으로 간주하지 않는다.

실제 서비스 연결 후 가입·인증·로그인·로그아웃·비밀번호 재설정·별도 브라우저 기록 복원을 확인하고, 인증 없는 접근과 다른 UID 접근·기존 대전 변경을 실제 API에서 거부하는지 확인한 뒤 배포한다.
