# 왁뿌볼 아레나

외부 라이브러리 없이 HTML, CSS, JavaScript로 만든 로컬 AI 전투 게임입니다.

## 실행

가장 간단한 방법은 `index.html`을 Edge, Chrome, Firefox 등의 브라우저에서 여는 것입니다. 인터넷 연결이나 설치가 필요하지 않습니다.

Node.js가 있다면 프로젝트 폴더에서 다음 명령으로 개발 서버를 실행할 수도 있습니다.

```powershell
npm start
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. 종료는 터미널에서 `Ctrl+C`를 누릅니다. 다른 포트를 사용하려면 `$env:PORT='5174'; npm start`를 실행합니다.

## 플레이

1. 처음에는 로비가 표시됩니다. **AI 난이도**에서 입문·초급·중급·고급을 선택하고 **싸우러 가기 ㅋㅋ** 버튼으로 AI 아레나에 입장합니다. 기본 선택은 기존 속도와 같은 초급이며, 재대전과 로비 복귀 후에도 선택이 유지됩니다.
2. 청록색 내 왁뿌볼을 클릭하거나 터치합니다. 키보드로 버튼에 초점을 맞춰 Enter/Space를 눌러도 됩니다.
3. 1~4회 타격에 따라 균열이 늘어납니다. 별도의 왁뿌볼 체력 숫자나 막대는 없습니다.
4. 5번째 타격 후 160ms 파괴 애니메이션이 완료되면 상대에게 정확히 10 피해를 주고 새 공이 생성됩니다.
5. 투사체 비행은 시각 효과입니다. 비행 중 다음 공을 파괴할 수 있으며, 도착 시 피해를 중복 계산하지 않습니다.
6. 양쪽 체력은 1000으로 시작합니다. AI도 5회 진행 후 파괴하며, 클릭 간격은 입문 1,500ms → 초급 850ms → 중급 450ms → 고급 200ms 순으로 짧아집니다. 전투 중 CPU 옆에 현재 난이도를 표시합니다. 난이도를 바꾸려면 로비로 돌아가 선택한 뒤 새 전투를 시작합니다.
7. 먼저 체력이 0이 된 쪽이 패배합니다. 종료 후 입력, AI, 예약 파괴와 추가 피해를 차단합니다.
8. **재대전** 또는 결과 화면의 **다시 도전** 버튼으로 모든 전투 상태를 초기화합니다. **로비로 돌아가기** 버튼은 실행 중인 프레임, 예약 공격과 시각 효과를 정리하고 로비로 이동합니다.
9. 로비의 **강화**, **도감**, **친구 대전**은 **아직 개발 안 함 ㅋㅋ** 안내를 표시합니다. 골드 시스템은 아직 없으므로 초기 보유 골드는 0 G이며 임의 보상은 지급하지 않습니다.

브라우저 탭을 숨기면 전투 시뮬레이션을 일시 중단합니다. 돌아오면 재개하므로 백그라운드 공격이 한꺼번에 쌓이지 않습니다. 동시 치명타는 먼저 등록된 파괴 완료 이벤트 순서로 처리하며 첫 종료 뒤 나머지 공격은 취소됩니다.

## 휴대폰 화면

휴대폰에서는 상단과 안내를 간결하게 표시해 공·체력·재대전을 화면 안에 배치합니다. 터치 기기의 안내는 ‘터치’로 표시하며 주요 버튼은 최소 44px 터치 영역을 제공합니다. 세로·가로 모드, 브라우저 도구 모음으로 줄어든 높이, 노치 안전 영역을 고려했습니다. 결과 화면은 모바일에서 화면 전체를 사용합니다.

## 설정 수정

`js/config.js`에서 다음 값을 조절합니다.

- `BALL_TYPES.common.hitsToBreak`: 파괴에 필요한 타격 횟수 (기본 5)
- `BALL_TYPES.common.damage`: 파괴 완료당 피해 (기본 10)
- `CONFIG.maxHealth`: 양쪽 초기 체력 (기본 1000)
- `AI_DIFFICULTIES`: 난이도별 이름과 AI 타격 간격 (`aiHitIntervalMs`, 양수로 지정)
- `CONFIG.defaultDifficulty`: 처음 선택되는 난이도 (기본 `beginner`, 초급)
- `CONFIG.destructionMs`: 파괴 완료까지의 시간 (기본 160ms)
- `CONFIG.projectileMs`: 투사체 시각 효과 시간 (기본 520ms)

현재 균열 그림은 일반 공의 4단계를 표현합니다. 추후 더 많은 파괴 횟수나 등급을 추가할 때는 균열 SVG/스타일도 함께 확장하세요. 파괴 시간을 바꾸면 CSS의 `break-ball` 애니메이션 시간도 맞추세요.

## 구조와 확장

화면 상태는 `lobby`, `battle`, `result`로 별도 관리합니다. `WaxArena.getScreen()`으로 현재 화면을 확인할 수 있습니다. 로비에서는 엔진을 대기 상태로 초기화하고 프레임 루프를 실행하지 않습니다. 전투 상태는 `waiting`, `running`, `victory`, `defeat`로 관리합니다. 전투 엔진은 입력(`hit`), 시간 진행(`advance`), 이벤트 출력(`drainEvents`)을 제공하며 화면에는 직접 접근하지 않습니다. 피해는 오직 `completeDestruction`에서 계산됩니다. 공마다 ID를 부여해 중복 완료를 막고, 재대전 시 라운드 ID와 예약 작업·이벤트 큐를 초기화합니다.

플레이어 화면에는 전투 로그를 표시하지 않습니다. 개발자 도구에서 `WaxArena.getDebugLog()`로 최근 전투 기록을 확인할 수 있습니다. 기록은 최대 40개로 제한하며 재대전 시 초기화합니다. 반환값은 복사본이므로 수정해도 내부 기록에 영향을 주지 않습니다.

화면은 한 개의 `requestAnimationFrame` 루프를 사용합니다. 종료 시 새 프레임을 예약하지 않으며 재대전 전 기존 프레임을 취소합니다. 시각 효과는 Web Animations API로 관리하고 모두 취소·제거할 수 있습니다.

실제 멀티플레이로 확장할 때 서버가 체력, 입력 검증, 시뮬레이션 시간과 승패를 관리하고 클라이언트 렌더러가 서버 이벤트를 소비하도록 어댑터를 추가할 수 있습니다. 이번 버전에는 네트워크, 인증, 강화, 수집, 레이드, 랭킹 기능이 없습니다.

## 테스트

전투 로직 테스트는 추가 설치 없이 실행됩니다.

```powershell
npm test
```

브라우저 테스트는 개발용 Playwright와 Chromium 또는 Edge가 필요합니다. 게임 실행 자체에는 필요하지 않습니다. 제공된 개발 환경에서는 번들 Playwright와 설치된 Edge를 사용했습니다. 다른 환경에서는 `playwright`를 개발 의존성으로 설치하거나 `PLAYWRIGHT_MODULE`에 모듈 경로를 지정하세요.

실행 중인 로컬 서버에 대해 다음 명령으로 검증합니다.

```powershell
$env:TEST_URL='http://127.0.0.1:5173'
npm run test:browser
```

기본 테스트 서버 주소는 `http://127.0.0.1:5174`입니다. `BROWSER_CHANNEL=chrome`으로 Chrome을 선택할 수 있습니다. 테스트는 실제 체력 1000을 그대로 사용하며 브라우저 시계를 제어해 긴 AI 전투를 빠르게 진행합니다. 데스크톱과 모바일 화면, 일반 클릭과 터치 입력, 빠른 연타, 승리·패배, 종료 후 무변경, 재대전 30회, 예약 파괴 중 로비 복귀 12회, 하단 메뉴 안내와 콘솔 오류를 확인합니다. `artifacts/lobby-desktop.png`, `lobby-390.png`, `lobby-320.png`에 로비 화면도 저장합니다.

휴대폰 전용 검증은 같은 서버에서 `npm run test:mobile`로 실행합니다. 320×568, 360×640, 375×667, 390×844, 412×915, 430×932, 667×375, 844×390 화면에서 주요 요소가 스크롤 없이 보이는지, 터치 영역이 44px 이상인지, 5회 실제 터치와 정확한 피해·재대전·로비 복귀가 작동하는지 검사합니다. 회전과 도구 모음으로 줄어든 화면 높이도 확인합니다. 결과 화면 배치 검사에만 테스트용 초기 체력 10을 사용하며 게임 설정 파일과 전체 체력 1000 회귀 테스트는 그대로 유지합니다. 결과는 `artifacts/mobile-results.json`, 화면 캡처는 `artifacts/phone-*.png`에 저장합니다.
