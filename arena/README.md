# 왁뿌볼 아레나

[가로로 플레이하기](https://gamjadough.github.io/Wax-Ball/arena/)

외부 라이브러리·이미지·폰트 연결 없이 실행되는 HTML/CSS/JavaScript AI 전투 게임입니다. 로비와 모드 선택은 제공된 배치 스케치를 반영했고, 공 캐릭터는 CSS와 SVG로 표현합니다.

## 온라인 계정

프로필 버튼에서 이메일 회원가입, 로그인, 인증 메일 재발송, 비밀번호 재설정과 로그아웃을 제공합니다. Firebase 연결 후 계정별 골드·전적을 다른 기기에서 이어갈 수 있습니다. 게스트 기록은 기존 브라우저에 별도로 보존합니다. 서버가 연결되지 않았을 때는 준비 중 안내를 표시하며 게스트 게임은 계속 실행됩니다. 서비스 구성과 검증 범위는 [Firebase 설정 안내](firebase/SETUP.md)를 참고하세요.

## 플레이

1. 로비의 **모드 선택** 영역은 현재 모드 글자, 여백, 화살표 어느 곳을 클릭하거나 터치해도 AI 대전·친구 대전·보스전·2대2 팀대전의 2×2 화면으로 이동합니다. 키보드 Enter/Space로도 열 수 있습니다. 현재 플레이 가능한 모드는 AI 대전입니다.
2. **AI 대전** 또는 로비의 **시작! 들이받아**를 누르면 난이도 팝업이 열립니다. **이놈으로 간다**를 눌러 전투를 시작합니다. 닫기 또는 Escape로 취소할 수 있습니다.
3. 내 라임색 공을 5번 클릭/터치하면 160ms 후 공이 파괴되고 상대에게 정확히 10 피해를 줍니다. 투사체는 시각 효과이며 추가 피해를 주지 않습니다.
4. 양쪽 체력은 1,000입니다. 먼저 0이 된 쪽이 패배하며 종료 후 추가 공격은 차단됩니다. 재대전은 선택한 난이도를 유지하고 모든 전투 상태를 초기화합니다.
5. 승리하면 난이도에 관계없이 **50 G**를 받습니다. 패배는 골드 보상 없이 패배 기록만 남습니다. 결과 화면에서 보상을 확인하고, 로비 상단에서 보유 골드와 승패 기록을 확인할 수 있습니다.
6. 골드와 전적은 같은 브라우저에 자동 저장되어 새로고침 후에도 유지됩니다. 중도 종료·전투 중 새로고침·전투 중 재대전에는 보상과 전적을 기록하지 않습니다. 결과가 확정된 한 대전에 보상은 한 번만 지급합니다.
7. 로비로 돌아가면 입력·AI·예약 공격·효과가 정리됩니다. 상점, 연구소, 친구 추가와 미구현 모드는 준비 중 안내를 표시합니다. 계정·레벨·골드 사용 기능은 아직 없습니다.

## 보상과 저장

`js/progress.js`가 `localStorage`의 `wax-ball-arena.progress.v1`에 골드, 누적 승패와 최근 100경기의 결과를 저장합니다. 각 대전에 고유 ID를 부여해 같은 결과의 중복 지급을 막고, 전투 결과가 확정되는 즉시 저장합니다. 다른 탭의 저장 변경도 골드·전적 표시에 반영합니다.

저장 데이터가 손상됐으면 게임을 중단하지 않고 새 기록으로 시작하며 다음 대전 결과부터 정상 데이터를 저장합니다. 브라우저가 저장을 차단하거나 저장 공간이 부족하면 현재 화면에서 기록을 유지하고 **저장 불가**를 표시합니다. 이 경우 새로고침 후에는 해당 기록이 사라질 수 있습니다. 브라우저 데이터 삭제 시 기록도 삭제되며 다른 브라우저나 기기로 자동 동기화되지 않습니다.

| 난이도 | AI 타격 간격 |
| --- | --- |
| 입문 | 1,500ms |
| 초급 (기본) | 850ms |
| 중급 | 450ms |
| 고급 | 200ms |

## 모바일

휴대폰과 터치 태블릿은 **가로 플레이 전용**입니다. 세로에서는 회전 안내를 표시하고 화면 입력, AI 및 진행 중인 공 파괴를 중단합니다. 가로로 돌아오면 이어서 진행하며 중단 시간 동안의 공격을 몰아서 적용하지 않습니다. OS의 자동 회전을 켜야 합니다. 브라우저가 기기 방향을 강제로 잠그는 기능에는 의존하지 않습니다.

`100dvh`, 안전 영역, 최소 44px 터치 영역을 사용합니다. 화면 높이가 낮으면 설명과 장식을 줄여 실제 조작을 우선합니다. 터치 기기에서는 파편을 6개로 줄이고, 모션 감소 설정에서는 파편·투사체를 생략합니다. 체력 텍스트는 값이 바뀔 때만 갱신하며 시뮬레이션은 단일 프레임 루프를 사용합니다. 숨긴 브라우저 탭에서도 전투를 일시 중단합니다.

## 실행·검증

`index.html`을 브라우저에서 직접 열거나 `npm start`로 http://127.0.0.1:5173 에서 실행합니다. 게임 실행에는 설치가 필요 없습니다. 브라우저 검증에는 Playwright와 Edge 또는 Chromium이 필요합니다.

```powershell
npm test
npm run test:progress
$env:TEST_URL='http://127.0.0.1:5173'
npm run test:lobby
npm run test:browser
npm run test:mobile
npm run test:rewards
```

테스트 기본 URL은 http://127.0.0.1:5174 입니다. `PLAYWRIGHT_MODULE`로 설치한 Playwright 경로, `BROWSER_CHANNEL`로 브라우저를 지정할 수 있습니다. `TEST_URL`에 공개 주소를 지정하면 배포 검증도 가능합니다. 로컬 파일 실행 검사는 작업 폴더의 파일을 사용합니다.

- `tests/battle.test.cjs`: 전투 규칙, 난이도별 AI, 승패·중복 공격·초기화 검증
- `tests/progress.test.cjs`: 보상 중복 방지, 저장 복원·손상·실패, 전적과 기록 범위 검증
- `tests/rewards.test.cjs`: 실제 결과 화면·골드·승패, 새로고침·중도 종료·다른 탭·저장 오류 및 작은 결과 화면 검증
- `tests/lobby.test.cjs`: 2×2 모드, 미구현 안내, 팝업 취소·초점 복귀, 실제 난이도별 공격 속도
- `tests/browser.test.cjs`: 균열·피해·재대전·로비 복귀, 실제 체력 1,000 승패, 결과 초점, 오프라인·모션 감소
- `tests/mobile.test.cjs`: 568×320부터 1024×768까지 9종 가로 크기, 실제 터치, 세로 회전 중 예약 파괴·AI 중단, 팝업 회전, 도구 모음 높이

결과와 캡처는 커밋하지 않는 `artifacts/`에 저장합니다. 최신 검증 내용은 `TEST_REPORT.md`를 참고하세요.

## 코드·배포

`index.html`과 `styles.css`가 모든 화면을 구성합니다. `js/config.js`에 난이도·파괴·체력 설정, `js/battle.js`에 DOM과 독립적인 전투 엔진, `js/progress.js`에 승리 보상과 브라우저 저장, `js/app.js`에 화면 전환·팝업·회전 중단·렌더링이 있습니다. 화면 상태는 `lobby`, `modes`, `battle`, `result`입니다. 읽기 전용 진단은 `WaxArena.getSnapshot()`, `getScreen()`, `getDebugLog()`, `getProgress()`로 확인하며 전투 로그는 최대 40개입니다.

검증을 통과한 변경을 커밋한 후 `./deploy.ps1`을 실행합니다. `Wax-Ball/main`을 가져와 별도 배포 체크아웃의 `arena/`만 갱신하고 푸시합니다. 배포 URL에서 파일과 게임 동작까지 확인한 후 배포 성공으로 보고합니다. 실제 멀티플레이·보스·팀대전·강화·상점 기능은 별도 구현이 필요합니다.
