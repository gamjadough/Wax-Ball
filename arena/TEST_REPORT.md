## 기존 전투 검증 이력

전투 로그 패널과 전용 스타일, DOM 갱신 코드를 제거했습니다. 하단을 조작 안내와 재대전 버튼으로 재배치하고, 개발용 기록은 최대 40개로 제한된 메모리 기록으로 분리했습니다. 추가된 로비 진입 흐름도 보존해 전체 브라우저 테스트를 다시 실행했습니다. 전투 로직 9개와 브라우저 검사 13개가 모두 통과했고 콘솔 오류는 0개였습니다.

화면 캡처 검토 중 재대전 직후 체력 막대가 이전 값에서 애니메이션되는 점을 발견했습니다. 초기화와 종료 시 체력 막대를 즉시 반영하도록 수정하고, 실제 막대 너비 검사까지 추가해 전체 브라우저 테스트를 다시 통과했습니다.

## 휴대폰 최적화 재검증

휴대폰의 전투 제목과 상단 여백을 줄이고 로비 복귀 버튼을 상단에 배치했습니다. 공·체력·재대전이 화면 안에 들어오도록 조정했고, 주요 조작 버튼에 44px 이상 터치 영역을 제공했습니다. 가로 전용 배치, 노치 안전 영역, 전체 화면 결과 패널, 터치 안내도 적용했습니다.

첫 검사에서 667×375 가로 화면의 재대전 버튼이 아래로 벗어났습니다. 가로 화면의 공 주변 여백과 불필요한 라벨을 줄이고 버튼 높이를 고정한 뒤 전체 휴대폰 검사를 다시 실행했습니다. 320×568, 360×640, 375×667, 390×844, 412×915, 430×932, 667×375, 844×390 모두에서 체력·공·재대전·로비 복귀를 스크롤 없이 조작할 수 있었고 수평 넘침이 없었습니다.

실제 터치 입력 5회, 피해 10, 재대전, 로비 복귀 후 AI 중단, 화면 회전, 390×650으로 줄어든 화면 높이, 모션 감소 설정과 결과 버튼 배치를 확인했습니다. 결과 배치 검사에만 체력 10 테스트 설정을 사용했습니다. 일반 게임 설정과 전체 브라우저 회귀 테스트는 체력 1000으로 유지했습니다. 모바일 검사 11개, 전체 브라우저 검사 14개, 전투 규칙 검사 9개가 통과했고 콘솔 오류는 0개였습니다.

## AI 난이도 추가 검증

로비에서 입문(1,500ms), 초급(850ms), 중급(450ms), 고급(200ms)을 선택합니다. 기본 난이도는 기존 속도를 유지하는 초급입니다. 전투 중 CPU 옆에 선택한 난이도를 표시하며, 재대전과 로비 복귀 후에도 선택을 유지합니다. 난이도 변경은 로비에서 다음 전투부터 적용됩니다.

네 난이도의 첫 클릭 시점, 다섯 번째 타격 후 정확히 10 피해, 속도별 파괴 시점, 난이도 변경 시 기존 예약 공격 정리, 잘못된 난이도 거부, 전체 체력 1,000의 패배와 종료 후 정지를 엔진에서 확인했습니다. 브라우저에서는 같은 시간 동안 난이도별 타격 횟수가 늘어나는지와 재대전·로비 복귀 후 속도 유지 및 예약 공격 취소를 검사했습니다.

375×667 화면에서 난이도 선택창 추가로 하단 메뉴가 화면 밖으로 밀리는 문제가 발견됐습니다. 작은 세로 화면의 여백과 캐릭터 크기를 조정하고 이름표 겹침을 개선한 후 모바일 11개 검사를 다시 실행해 모두 통과했습니다. 초기 Edge 실행과 접속 실패는 샌드박스 환경 격리 문제였으며 서버와 브라우저를 같은 환경에서 실행해 해결했습니다.

## Firebase 서버 구성 진행 (2026-10-13)

Firebase CLI 15.33.0을 확인하고 사용자 Google 계정으로 로그인했다. Google Cloud 프로젝트 `wax-ball-arena-gamjadough`(표시 이름 Wax Ball Arena)는 생성됐다. Firebase 추가 요청은 실제 API에서 403 PERMISSION_DENIED를 반환했다. Firebase 콘솔에서도 약관 동의 상태 및 프로젝트 목록 로딩 오류가 확인돼 계정 초기 설정 완료를 요청했다. 기존 프로젝트에 추가를 재시도하며 별도의 프로젝트를 반복 생성하지 않았다.

`firebase.json`에 이메일/비밀번호 인증과 승인된 게임 도메인·로컬 테스트 도메인, Realtime Database 규칙 경로를 준비했다. `.firebaserc`는 위 전용 프로젝트를 지정한다. 설정 파일 3개의 JSON 파싱은 통과했다. 이 설정은 아직 Firebase에 배포되지 않았으며 서비스 연결 설정도 비어 있다. 계정 활성화와 실제 검증이 끝나기 전에는 게임 공개 배포를 진행하지 않는다.

## Firebase 실제 서버 검증 및 활성화 (2026-10-13)

사용자가 Firebase 약관 동의 후 생성한 `waxball-arena` 프로젝트를 사용한다. 이전 Google Cloud 전용 프로젝트 대신 `.firebaserc`와 승인된 도메인을 실제 프로젝트에 맞췄다. 등록된 웹 앱의 공개 설정을 account-config.js에 적용했다. Realtime Database는 asia-southeast1에 생성했고, `deploy --only auth`와 `deploy --only database`가 성공했다. 데이터베이스 규칙은 실제 Firebase 구문 검사와 배포를 통과했다.

실제 Firebase 서버 검사 7개를 통과했다: 발송 없는 가입·미인증 로그인/저장 차단, 비밀번호 로그인·서버 프로필 확인, 동일 대전 1회 기록과 별도 세션 기록 복원, 인증 없는 접근·타인 조회·기존 결과 수정/삭제·추가 보상 필드 거부, 토큰 갱신, 저장 대기열 전송과 패배 0골드, 로그아웃. 실제 브라우저에서도 로그인→승리→온라인 저장→별도 브라우저 복원→다른 계정 분리→로그아웃을 통과했다. UI 승리 검사는 테스트에서만 체력 10을 사용하며 서비스 게임 설정은 체력 1,000을 유지한다.

검증용 계정은 example.invalid 이메일과 무작위 비밀번호로 분리했다. 자격 증명은 Git에서 무시하는 artifacts 아래에만 저장한다. 이메일 발송 없는 실제 가입 검사에서 만든 계정은 삭제했다. 실제 인증/재설정 이메일 수신·링크 클릭은 검증하지 않았다. 실제 Gmail 별칭으로 이메일을 보내는 테스트는 자동 승인 검토가 별도 승인 없는 외부 발송으로 거부했으므로 실행하지 않았다. 메일 발송 요청 UI와 오류 처리 흐름은 가상 서버 브라우저 검사로 확인했다.

실제 Firebase 연결 이후 가상 서버 계정 UI 검사 8개와 계정 로직 검사 8개도 다시 통과했다. 실제 브라우저 검사 스크립트의 Windows 기본 문자 인코딩 문제는 UTF-8 명시로 수정했다.
