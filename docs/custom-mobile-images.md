# 모바일 커스텀 사진 미리보기 보완

기존 코드에서 4,096px 초과 사진을 디코딩 후 거부하고, `createImageBitmap`을 사용할 수 없거나 옵션을 거부하면 대체 경로 없이 실패하는 것을 재현했다. 오류 안내가 편집창 맨 아래에만 있어 파일 선택 위치에서 놓치기 쉬웠다. 신고자의 실제 기기/사진 형식은 아직 확인하지 않았으므로 특정 기기의 단일 원인으로 단정하지 않는다.

사진은 파일 크기와 PNG/JPEG/WebP 헤더를 먼저 확인하고 편집용 캔버스의 긴 변을 최대 2,048px로 제한한다. 원본 20MB 이하, 각 변 32~16,384px, 총 6,400만 화소 이하를 허용한다. ImageBitmap에는 축소를 요청하고 API가 없거나 거부하면 object URL과 HTML 이미지로 읽는다. 회전 정보는 브라우저의 원본 방향 처리를 유지한다. MIME이 비어 있어도 실제 지원 이미지 헤더로 판별한다. SVG 등 다른 형식과 과도한 크기는 디코딩 전에 거부한다. HEIC/HEIF는 JPG/PNG 변환 안내를 제공하며 별도의 변환 라이브러리는 추가하지 않는다.

읽기 상태와 오류를 파일 선택 바로 옆에 표시한다. 세로 모바일에서는 성공 시 원형 미리보기로 이동한다. 같은 파일을 다시 선택할 수 있고, 파일 선택창 취소는 기존 사진을 유지한다. 편집창 닫기/볼 변경/계정 변경/다른 사진 선택 시 이전 작업을 취소하며 늦은 결과는 반영하지 않는다. ImageBitmap과 object URL은 정리한다. 읽기에는 시간 제한이 있다.

서버에는 기존과 동일한 512px PNG만 전송한다. 원본 파일은 전송하지 않으며 가격·이용권·보상·서버 검증·비공개 저장 정책은 변경하지 않는다. DB/Edge Function 배포는 필요하지 않다.

`python tools/custom-mobile-images.py`는 실제 파일 입력, PNG 저장과 재열기, EXIF 방향, 큰 JPEG, MIME 누락, WebP, API 부재/옵션 거부, 잘못된 파일/HEIC/과도한 해상도, 재선택/취소 및 터치 화면을 검증한다. Edge와 WebKit 390×844, 844×390 에뮬레이션이며 실물 아이폰/갤럭시 또는 Safari 앱 자체 검증은 아니다. Python Pillow, 기존 Playwright 의존성과 설치된 WebKit 엔진이 필요하다. 로컬 계정과 가짜 저장소만 사용한다.
